# User needs discovery

Первый пользователь — **продвинутый вайбкодер** (сам автор проекта): много
параллельных Claude/opencode/codex-сессий, свои MCP, Session Manager, боты,
десятки репозиториев. Хочет «API serverless-агента как воркер»: кинул задачу —
получил результат, не держа терминал открытым.

Статус: **гипотезы + интервью 2026-09-27**. Ответы — в конце документа.

## Jobs to be done (гипотезы)

| # | Работа | Сейчас как решается | Боль |
|---|---|---|---|
| J1 | «Сделай issue → PR» без моего терминала | Session Manager на ноутбуке | ноутбук должен быть включён; сессии мешают друг другу в одном чекауте |
| J2 | Фоновая работа по событию (вебхук GitHub, сообщение в Telegram-боте, cron) | ручной запуск | нет места, куда событие может «позвонить» |
| J3 | Дешёвые массовые прогоны (исследование, скрейпинг, обработка пачки файлов) | руками по одному | параллельность, стоимость, потеря результатов |
| J4 | Встроить агента в свой продукт (trained-assist, боты) как бэкенд-функцию | прямой запуск CLI на хосте | нет изоляции, нет диагностики, нет лимитов |
| J5 | Понять, почему агент не справился | читать логи сессии | логи теряются, нет категорий |

## Гипотезы требований и что есть в V0

| Требование | V0 |
|---|---|
| `POST` задачи → `run_id`, не держать соединение | ✅ |
| Вебхук с подписью на события и завершение | ✅ |
| Результат: текст + файлы | ✅ `/artifacts` |
| Доступ к GitHub: клон приватного репо, push, PR | ⚠️ клон есть; push/PR — если передать `GITHUB_TOKEN` как секрет, агент может, но это не оформлено как фича |
| Свои креды (credential store) агенту по имени | ⚠️ серверный файл секретов, без per-user хранилища |
| Выбор агента (opencode / claude / codex) и модели | ⚠️ только opencode, модель — любая OpenRouter |
| Свои модели/эндпоинты (бесплатные, свои ключи) | ⚠️ только OpenRouter |
| Продолжить диалог с тем же агентом | ❌ |
| Стрим прогресса в реальном времени | ✅ SSE |
| Понятная причина падения | ✅ `diagnosis` |
| Параллельные раны | ⚠️ `SAR_MAX_ROOMS=1` на e2-small |
| Внешний HTTPS-эндпоинт (не SSH-туннель) | ❌ |
| Триггеры (cron, GitHub-вебхук → ран) | ❌ |
| CLI/SDK, чтобы вызвать одной строкой | ❌ только curl |
| Стоимость / учёт токенов по рану | ⚠️ tokens в результате; денег нет |
| Сохранение состояния между ранами (память, кэш репо) | ❌ каждый ран с нуля |
